# Docker и compose

Как устроен стек, какие команды есть и что делать, если что-то не поднялось. Запуск с нуля описан в [README](../README.md).

## Сервисы

| Сервис | Что делает | Порт на хосте |
|---|---|---|
| `db` | PostgreSQL 16, данные в томе `pgdata` | - |
| `redis` | брокер Celery, шина живой панели и пульс воркера | - |
| `backend` | API (uvicorn), при старте накатывает миграции | `8000` (`BACKEND_PORT`) |
| `worker` | фоновые задачи Celery: письма, нейросеть | - |
| `beat` | расписание: напоминания, отправка писем, чистка | - |
| `mailpit` | только в режиме разработки: ловит все письма | `8025` |

`backend`, `worker` и `beat` собираются из одного образа `backend/Dockerfile` и отличаются командой. `worker` и `beat` стартуют после того, как `backend` прошёл healthcheck, то есть миграции уже применены.

У всех сервисов `restart: unless-stopped`, логи пишутся с ротацией: до трёх файлов по 10 МБ на сервис.

## Команды

| Команда | Что делает |
|---|---|
| `make up` | собрать и поднять стек в фоне |
| `make down` | остановить стек, данные базы остаются |
| `make ps` | состояние контейнеров |
| `make logs` / `make logs s=worker` | логи всех сервисов или одного |
| `make restart s=worker` | перезапустить один сервис |
| `make psql` | psql в базе стека |
| `make shell` | shell в контейнере бэкенда |
| `make db-backup` | резервная копия базы в `backups/` |
| `make db-restore f=backups/<файл>.sql.gz` | восстановить базу из копии |

## Режим разработки и сервер

`docker compose up` сам подхватывает `compose.override.yaml`: режим разработки, демо-данные и Mailpit. На сервере запускаем только `compose.yaml`: `docker compose -f compose.yaml up -d`. Подробнее в разделе README «Развёртывание на сервере».

## Если не работает

- **Порт 8000 занят.** `BACKEND_PORT=8001 docker compose up`.
- **`/api/v1/health` отвечает `degraded`.** Стек работает с ограничениями: без ключа нейросети работает заглушка. Для локального запуска это нормально.
- **`/api/v1/health` отвечает 503.** Недоступна база или Redis: `make ps` и `make logs s=db` / `make logs s=redis`.
- **Нужна чистая база.** `docker compose down -v` удаляет том `pgdata`, при следующем запуске миграции и демо-данные накатятся заново.
- **Письма не видно.** В режиме разработки они лежат в Mailpit: http://localhost:8025.
